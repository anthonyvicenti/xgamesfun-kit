|---|---|

| `?bots=N` | Fills seats |

## 2. Assets: everything visible is a slot

### 2.1 Runtime (`kit/assets/assets.js`; K1)

```js
import { assets } from './gf/three/assets/assets.js';
const tree   = await assets.model('prop.crate');        // a clone of the slot's GLB, every mesh tagged userData.gfSlot = 'prop.crate'
const body   = await assets.model('character.body.player');
const tex    = await assets.texture('world.ground.albedo');   // THREE.Texture, colour space from the slot's constraints
const v      = assets.value('look.sun.intensity');        // a value slot, read through gf-assets (overrides applied)
const cfg    = assets.config('game');                     // the whole config/game.json (overrides applied)
assets.tag(object3d, slotId);                             // for kit primitives whose material is a slot (R1)
const report = assets.coverage(scene);                    // { meshes, tagged, untagged: [{name, path}] }; verify needs untagged = []
```

- Reads go through `gf/gf-assets.js`, so Studio overrides, packed mode and `__GF_ASSETS_SEEN` all work unchanged.
- GLBs are cached per slot and cloned per use (`SkeletonUtils.clone` for skinned meshes). Loaders: GLTFLoader with Meshopt, Draco and KTX2.
- A slot whose file is missing is an error, never a silent fallback. The exception is a slot declared `optional` with an explicit kit default.

### 2.2 Declarations (`slots.mjs`; K1 owns the tool, every module declares)

Every module exports `slots` (an array of slot templates). `create` and `node tools/slots.mjs <game> --write` assemble `assets.json` from them. The sources are:
- the kit's own modules (look, world, character, mechanics);
- `config/*.json`;
- the files under `assets/`.

A template is an ordinary gf-assets/1 slot: `id`, `label`, `group`, `type`, `source`, plus `constraints`, `generate`, `license`, `tier` and `facet`. It may carry `{param}` placeholders that the module fills from its params.

| Slot ids | What they are |
|---|---|
| `character.body.<role>` | Body model (`constraints: { rigged: true, rig: "gf-humanoid-1", animations: [...] }`) |
| `character.tint.<role>` | Tint |
| `character.hat.<role>` | Hat (optional) |
| `prop.<name>` | A prop |
| `world.<template>.<part>` | A part of a world template |
| `look.<group>.<name>` | Look values |
| `mechanic.<id>.<name>` | Mechanic values and models (e.g. `mechanic.projectile.model`, `mechanic.projectile.color`) |
| `rules.<name>` | Values the game agent exposes from `config/game.json` → `rules` |
| `ui.<name>` | UI text and colours |

Main tier: at most about 40 slots. The rest are `"tier": "advanced"`.

### 2.3 Coverage (R3)

`assets.coverage(scene)` walks visible meshes (`visible`, in the frustum or not, `material.visible`). Exempt only when `userData.gfExempt` holds a reason, for things like debug helpers or a ray-cast proxy. `verify` fails when `untagged` isn't empty.

## 3. The game agent's surface: `rules.js`

```js
export default {
  // Called once on every copy, after the world, players and mechanics exist. Register shared state, UI, listeners.
  setup(ctx) {},
  // Every copy, when the round starts (the same moment for everyone).
  roundStart(ctx) {},
  // Every frame on every copy. dt is in seconds. Keep host-only logic under `if (ctx.host)`.
  update(ctx, dt) {},
  // A gameplay event from another copy: ctx.net.send(name, data, to) on their side.
  event(ctx, name, data, from) {},
  // Host only: is the round over? Return null, or { winners: [playerId], reason }.
  check(ctx) { return null; },
  // Every copy, at round end. Return the rows for the results screen.
  results(ctx) { return ctx.players.list().map(p => ({ id: p.id, name: p.name, value: p.score })); },
  // Optional: steer a bot each frame (host owns bots).
  bot(ctx, player, dt) {},
};
```

**`ctx`** (K1 builds it; the modules hang off it):

| Field | What it is |
|---|---|
| `THREE`, `scene`, `camera`, `renderer` | the three.js objects |
| `physics` | the Rapier world (kit steps it; fixed 60 Hz) |
| `config` | `config/game.json` (`ctx.config.rules` is the game agent's own params) |
| `rng()` | seeded 0–1 random. Gameplay never calls `Math.random` |
| `time` | `{ now, round, left }` (seconds) |
| `host` | true on the copy that owns shared state (also true when playing alone) |
| `me` | the local player |
| `players` | `list()`, `get(id)`, `others()`. Each player has `{ id, name, color, isBot, local, score, alive, data: {}, character, body, pose }` |
| `world` | `{ template, spawn(i), zone(name), props: Map, raycast(from, dir, max) }` |
| `mechanics` | `get(id)` → the instance `create` configured from the spec |
| `shared` | host-owned state replicated to every copy: `register(key, initial)` → proxy; the host writes, others read; sent through `net.world` |
| `net` | `send(name, data, to='all'\|'host'\|playerId)`, `on(name, fn)`. Events are edges, never per frame |
| `ui` | `meter(id, opts)`, `score(rows)`, `banner(text, secs)`, `toast(text)`, `prompt(text)`, `timer(on)`, `goal(text)` (§6g) |
| `hud`, `menu` | the kit's HUD and home menu (§6g): read only for rules (`hud.goalText`, `menu.view`) |
| `audio` | `play(soundId, opts)`, the gf-audio sounds in `assets.json` |
| `assets` | §2.1 |
| `round` | `{ phase: 'lobby'\|'countdown'\|'playing'\|'results', end(reason) }` (host) |

The kit owns:
- the frame loop (`net.loop`);
- the home menu (title screen, How to play, Settings, the wallet), the pause menu, the countdown, results and replay (§6g);
- the HUD's player card: health, knocked down or out, each mechanic's meter, the goal line and the menu button (§6g);
- spawning players and bots;
- local movement through the controller, and sending and drawing poses;
- drawing friends as characters with nameplates;
- the camera;
- quality tiers.

`rules.js` owns only what makes this game this game.

## 4. Module interfaces

### 4.1 Mechanics (K2): `kit/mechanics/<id>/index.js`

```js
export const id = 'projectile';
export const params = { /* JSON Schema of the spec's params for this mechanic */ };
export const slots = [ /* slot templates (§2.2) */ ];
export function create(ctx, params) {
  return {
    update(dt) {},              // every copy
    hostState() {},             // optional: small snapshot for ctx.shared (host)
    applyState(s) {},           // optional: non-host copies
    event(name, data, from) {}, // optional: listens to its own events, prefixed `<id>:`
    dispose() {},
    // plus the mechanic's own methods, documented in its README.md (e.g. fire(player, dir), coverage(), spawnWave(n))
  };
}
```

Wave-1 ids (PLAN §2.1):

| Id | Mechanic |
|---|---|
| `projectile` | Discrete and continuous streams, arcs, hits, splash |
| `paint` | Surface coverage per player or team; territory score |
| `pickup` | Consumables that refill or modify a player's meters; respawn |
| `health` | Health, knockback, ragdoll and get-up, respawn |
| `carry` | Grab, carry and throw props or players |
| `waves` | Host-owned enemies, spawners, a target to defend |
| `station` | Interact with a prop: an in-world screen or panel UI, timed tasks, quotas |
| `race` | Checkpoints, laps, a finish order |
| `tag` | Roles that pass between players on contact, hide and seek |
| `teams` | Team assignment, team score |
| `melee` | A weapon you swing (2026-10-08, CONTRACT §8): a weapon table of combo chains (windup, active, recover, arc, reach, damage, knockback, hit-stop, lunge), a heavy attack, a dash with invulnerable frames; swings follow `p.aim`; hits read as §6f; local hit-stop and shake only; the weapon on `hand_r`; bots swing |
| `levels` | A run of levels (2026-10-08): each level's encounter, then its portal opens; everyone in the portal moves to the next level (`ctx.world.setLevel`, `p.teleport`); the last level is the boss's; a lost run restarts at level 1 |
| `boss` | One big enemy with phases (2026-10-08): its own body role and scale, telegraphed slam, charge, volley and summon, a named health bar across the HUD top |
| `loot` | Drops and choices (2026-10-08): coins and potions on kills, chests (interact), weapon drops that swap the melee weapon with a rarity colour, one of three upgrade cards between levels |

`waves` also takes enemy **`types`** (2026-10-08; a spec with none plays as before): each with a body role, hp, speed, damage, reach, a `behaviour` (`chaser`, `lunger`, `ranged`, `brute`, `shielded`), a telegraph and a score; **attack tokens** let at most N enemies swing at once. In a scenic game, `create` fills the action mechanics' models from the scenic library (melee weapons, a type's or the boss's `weapon` given as a library id such as `kaykit-skeleton-axe`, loot's chest, coin and potion) and adds their sounds (`melee-*`, `enemy-*`, `boss-*`, `portal-*`, `loot-*`).

Each mechanic must:
- carry a 2-player fixture in `kit/mechanics/<id>/fixture/`;
- handle the netcode traps in PLAN §2.6;
- keep every message within the gf-multiplayer limits: 4 KB a message, at most 60 messages per player per second, `net.world` at most 3.5 KB.

### 4.2 Look (L): `kit/look/look.js`

export function createRenderer(canvas, preset, quality)  // WebGLRenderer + tone mapping + shadows from the preset

- A preset is plain JSON. Every number and colour in it becomes a `look.*` slot.
- Materials accept a tint. Lighting and post settings are tuned per quality tier.

### 4.3 World (L): `kit/world/world.js`

```js
export async function loadWorld(ctx, worldConfig)   // template + layout → meshes (all slots), colliders, spawns, zones
export const templates = ['backyard', 'office', 'plaza', 'arena', 'store']
export async function templateLayout(id, { size, seed })   // the template's recipe expanded at a size class
```

- **Templates are recipes; layouts are generated (worlds track, 2026-10-07).** `kit/world/generate.js` (pure; create, upgrade, the lint and the browser share it) turns a template's recipe, a size class (`small` | `medium` | `large`, the spec's `world.size`) and a seed (the title's hash) into the concrete `config/world.json`. An **indoor** recipe (office, store: a supermarket) is a closed building: bands of side rooms round the main room, doorways joining them (a spanning tree from the main room, loops from medium up), doors to the street for the rooms marked `entry`, walls on a 2 m module with windows, a ceiling, lamps, each room dressed by its zone recipe from the template's furniture groups, and a street with city blocks outside. An **outdoor** recipe keeps its hand-dressed small layout, grows it for larger classes and closes its edge (`edge`, `gates`).
- **Indoor layouts** add `kind: "indoor"`, `sizeClass`, `rooms: [{id, kind, label, rect: [x0,z0,x1,z1], main}]`, `doors: [{at, rooms: [a, b], normal, width}]`, `entries: [{name, room, at, normal (outward), width}]` and `ceiling: {height, color, color2, glow, band, pattern}`. The ceiling is a kit primitive drawn as a **cutaway**: it faces down (seen from inside, culled from above) and fades as the camera rises to it, with what hangs from it; a band (slot `world.<t>.ceiling.band`) closes the walls up to it. Slots `world.<t>.ceiling.color`, `.band`, `.pattern`.
- **ctx.world** adds `kind`, `sizeClass`, `rooms`, `doors`, `entries`, `roomAt(x, z)`, `via(from, to)` (the next point toward another room, through its doors; the waves mechanic and the bots walk through it) and `entry(rng)` (a point just inside a real door or gate: the waves mechanic brings enemies in there). Spawns in a world with rooms face the main room's centre zone.
- **Colliders** may be `{shape: 'compound', parts: [...]}` (a doorway: two posts and a lintel, so the opening is real); `library/props.json` doorways carry `door: {width, height}`.

- A layout is JSON: `{ template, props: [{ prop, at:[x,y,z], rot, scale }], spawns: [[x,y,z]...], zones: { name: { shape, at, size } } }`. `rot` is in **degrees** (yaw, or `[x,y,z]`).
- Colliders come from simple shapes declared per prop in `library/props.json`.
- **Set dressing (assets track, 2026-10-06):** `ground.pattern` (slot `world.<t>.ground.pattern`, a baked CC0 texture: paving, carpet tiles, lawn stripes, checker) keeps every floor readable; `library/props.json` entries carry `real` (the real-world size the lint compares against a 1.7 m character) and `hosts` (what may stand on or inside them, e.g. a planter hosts a tree). Pickups draw the game's own prop (`mechanics[pickup].params.prop`) and their ground ring is `params.marker` (`auto` | `ring` | `none`). The lint `tools/dressing.mjs <game | template>` (rules and thresholds in `tools/lib/dressing.mjs`) is verify check 11; `research/studio-v2/prompts/look-rubric.md` is the agent's eight-question look review (the worker writes it into each build and revise job as `LOOK.md`). The contact sheet adds a `top` plan shot, and no shot starts inside or behind a prop.

### 4.5 Controller (K1): `kit/controller/controller.js`

```js
createController(ctx, { character, camera: 'third'|'first'|'top', speed, jump })
// → { update(dt), pose() /* for net */, teleport(p), aimAt(point | null), enabled }
```

- Keyboard and mouse, plus touch, through `kit/core/input.js`.
- `ctx.me.aim` is a normalised direction. In third and first person it points from the aim origin (feet + 1.2 m) at the point under the crosshair, and `ctx.me.aimDist` is how far that point is (§6d). Bots and the top camera have no `aimDist`.
- `ctx.me.actions` is `{ primary, secondary, interact, jump }` with edge flags.

### 4.6 Net (K1): `kit/net/`

- Wraps `gf/mp/net.js`.
- **Poses:** sent by the kit. The fields are `{x, y, z, yaw, anim, aim, ad, lk, extra}` (`ad`: the aim distance, §6d; `lk`: the player's loadout key, §6e, absent without a loadout). A mechanic may add small numbers to `extra`, for example a stream's on/off and pressure.
- **Shared state:** `ctx.shared` is batched into one `net.world` message. Numbers that must not blend are sent as strings or read from `latest` (net.js header).
- **Alone:** `net.active` is false, and the same code runs for one player plus bots.

### 4.7 Flows (open builder M4-C, 2026-10-11): `kit/loops/<id>/index.js`

How a round is played is a part a game picks (`spec.loop` → `config/game.json` → `round.flow`, `round.params`); `kit/loops/README.md` is the interface.

- **What a flow owns:** everything while the phase is `playing`: whose clock, who may act, what ends it. The lobby, countdown, results, replay, players and net stay the session's (`kit/net/session.js`) for every flow.
- **The flows:** `round` (the timed round; the default, and what every game made before this ran), `turns` (`ctx.turns`; rules hooks `move`, `turnStart`, `turnTimeout`, `botMove`), `match` (`ctx.match`; rounds won are the score), `endless` (no clock; `check` is the only end). `saved` is not built. A world (§9) is a mode of the session, not a flow.
- **`round.seconds`:** the length of a round for `round` and `match`; for `turns` and `endless` it is optional and caps the whole session. `ctx.time.left` is what the HUD's clock shows: the round's, a turn's, or `Infinity` when there is none.
- **Bots alone:** the flow says how many (`botsAlone`): `turns` seats `players.min - 1` (at least one), the others fill every seat. `?bots=N` still asks for a number.
- **The observation:** `snapshot().flow` is what a flow publishes (`turns`: `{id, order, turn, moves, passed, refused, left, why}`); a flow's shared state is in `snapshot().shared` under its manifest's `state.key`.
- **The checks:** a flow's manifest carries its signs. Check 12 reads `signs.pulse` (turns: moves played in turn; a timed round: a score that moves), check 15 `signs.sample` and `judge`, check 13's fallback `signs.pressed`, and the 25 s solo round adds `signs.short` (`tools/lib/flow-signs.mjs`).

## 5. The observation and the verify gate

- **`window.__game`** (K1): `{ kit: 'gf-three', version, phase, players: [{id, name, score, alive, x, z}], snapshot(), seed, quality }`. `snapshot()` holds no functions and is stable for the same seed.
- **`node research/gf-three/tools/verify.mjs <game> [--out evidence/verify-N] [--quick]`** prints a single verdict and writes `verdict.json`. The checks are:

|---|---|
| 1 | `assets.json` valid (`research/asset-manifest/validate.mjs`), its slot ids exactly the ones the declarations give (`tools/lib/manifest-check.mjs` against `assembleManifest`: a slot the kit modules, `config/*.json` or a file under `assets/` declares and the file lacks is put back by `tools/fix.mjs` before verify, with a note; a slot nothing declares fails and is named; a round game's flow only), and `multiplayer.json` valid |
| 2 | Kit copies unedited (`gf/three`, `gf/mp`, `audio`) |
| 3 | Boots to play with no console errors (real input through `research/foundations/qa/browser.mjs`), and the player moves on real keys: the body, or, in a game whose part owns `player.control` by its manifest (a board with a cursor), the mark that part reports (`presence(p)` → `snapshot().players[].mark`; `tools/lib/part-signs.mjs`). The solo round's test player also takes its own turn when a part lists one (`controls().points`, or `interactables` marked `turn: true`; `tools/lib/turn-player.mjs`), so checks 7, 12 and 15 read a round in which the person played |
| 4 | Slot coverage 100% (§2.3), and the game's own code builds nothing to draw (`tools/lib/improvised-check.mjs`: no `new` geometry, mesh, sprite, points or line in `rules.js` or any other script of the game outside `gf/`, `vendor/` and `audio/`; what a game shows comes from a slot's file or a kit part. A reading of the source; a round game's flow only) |
| 5 | Two-player live gate (`research/multiplayer/party/gate-live.mjs` or its gf-three adapter): each screen shows the other player where they really are, and the shared state matches. Plus the loadout leg (§6e, `tools/lib/loadout-check.mjs`): two players in different test loadouts each draw the other in their own body colour (read from the body's material) and shot colour (a stream's from its material; a discrete shot's as each copy resolves it for the shooter); a change mid-round and a reloaded copy follow |
| 6 | A round runs to results and replays, alone with bots and with two players |
| 7 | Audio gate v5 (`research/audio/qa-gate-v5.mjs`; a world and a forge game: v4 in their own flows). Over the solo round: the loudest sound, over the 100 ms it is loudest, reaches -32 LUFS (v4 read the loudest 400 ms against the same number, which a game of single short sounds never fills: board and panel games failed by 0.5 to 4 LU at the kit's own levels); at least 2 sounds of 2 kinds started and 8 in 10 of those that started reached the speakers; when the kit counts plays (`window.__game.sounds()`), one of the game's own listed sounds played when it lists two or more (not on the `ui` bus); and v4's ceilings unchanged (integrated, short-term, true peak, harshness, clipping, 12 sounds in 100 ms, silence while hidden). The kit's bus levels are never raised to pass |
| 8 | Swap proof: one body and one prop slot replaced by override, and the new model is visible |
| 9 | Contact sheet on the real GPU (four cameras, `--quick` skips) and perf numbers |
| 10 | Fair play (§6c): a scripted human vs 3 bots for 42 s, twice at once (stands and fights; wanders and sprays), real keys, no `?gf-calm`. Fails when the player is out of control longer than `fair.downSeconds` + 1 s at once while alive, is in control under 85% of the time alive, or a protected player is knocked. ## 6c. Fair play (kit-owned, on by default; 2026-10-06)

The creator on the first T1 build: "people kept knocking me down and I couldnt get up. The knock down timer was also pretty long." So fairness is the kit's job in every game, with no agent effort. The rules are in `kit/core/fair-logic.js`, the runtime is `kit/core/fair.js` (`ctx.fair`), and the bots' helper is `kit/bots/bots.js` (`ctx.bots`).

| | The kit guarantees |
|---|---|
| F1 | A knock takes a player out of control for `downSeconds` (1.2 s) at most, from the hit to walking again. That is a short ragdoll tumble, then the get-up clip played faster. |
| F2 | A player who is down (knocked, ragdolled, getting up, or out) takes no damage and no knocks, and hits on them count for nothing. |
| F3 | Once control returns, the player has `protectSeconds` (1.5 s) of protection: no knocks, no damage, no counted hits. Their body shimmers in the `fair.protect-color` slot (an emissive glow on its own materials, no new art). |
| F4 | After a respawn, protection counts from when the player can move. The respawn point is the spawn farthest from the other live players, unless the game set `health.respawnZone`. |
| F5 | For the first `startGrace` (2 s) of a round, no hit counts and bots hold fire. |
| F6 | Continuous attacks (stream ticks, contact damage) push but never knock over. Knock-overs need a discrete hit: a shot, a splash, or a tag with knock. |
| F7 | Bots pick targets that can be hit and spread across them. They react and aim like people (`botSkill`, 0.35 by default, is friendly). At most `botsPerTarget` (1) bots may hurt one human at a time. Every bot holds fire in the grace and while aiming at a player who can't be hit, whatever `rules.bot` asks. |
| F8 | `projectile.onHit`, `health.onDamage` and `waves.onPlayerHit` fire only for hits that counted. A hit fair play refused goes to `projectile.onBlocked` (`why`: `out`, `down`, `protected`, `grace`, `busy`). Rules that score in those callbacks can't farm a helpless player. |

**Config.** `config/game.json` → `fair`: `{ on, downSeconds, protectSeconds, startGrace, botSkill, botsPerTarget, respawnFar, protectColor }`.
- `create` writes it with the defaults (`FAIR_DEFAULTS`). A game without the block gets the same defaults.
- Every value is a `fair.*` slot. Three are main tier: `fair.down-seconds` ("Seconds down after a knock"), `fair.protect-seconds` and `fair.bot-skill`.
- `health.getUpSeconds` and `projectile.knockSeconds` apply only with fair play off.
- Turn any of it off only when the creator asks.

**API** (host decides; the other copies show).

| Call | What it does |
|---|---|
| `ctx.fair.canHit(p, {from})` | Does a hit on `p` count now? |
| `ctx.fair.blocked(p, {from})` | Why a hit doesn't count, or null |
| `ctx.fair.state(p)` | `'control'`, `'down'`, `'protected'` or `'out'` |
| `isDown(p)`, `isProtected(p)`, `grace`, `protect(p, secs)` | Read or set the same state |
| `params`, `split` | The values; `split` is `{total, ragdoll, getup}` for one knock |
| `p.knock(v, secs, {out, force})` | The host refuses (→ false) a knock on a player who is down or protected; `force` skips that for a deliberate knock. A knock lasts `downSeconds` in all; `{out: true}` keeps the player down until revived |
| `p.push(v)` | A shove that never knocks over |
| `health.damage(t, n, {push: true})` | A continuous hit: it damages and shoves |
| `ctx.bots.target(bot, {range, prefer})` | A player that can be hit, spread across bots; `prefer` is `'spread'`, `'nearest'` or `'leader'`. Null in the grace |
| `ctx.bots.attack(bot, t, {stop, action, hold})` | Seek, aim with human error, and hold `action` once ready |
| `ctx.bots.aim(bot, t)`, `ctx.bots.ready(bot)` | The parts of `attack` |

**Observation.** `window.__game.snapshot().players[i]` adds `control`, `down`, `protected` and `pl` (protection seconds left; host). `snapshot().fair` holds the values, `grace`, and stats (knocks, refused knocks, blocked hits by reason).

## 6e. Player looks and loadouts (kit-owned, on by default; wallet phase 1, 2026-10-07)

The creator: "Eventually users will need to have the option to sign in with a wallet. We will have to be able to check their wallet for certain NFTs as in game items. For example, an NFT that represents a character color or pee stream color. This needs to be visibile from multiplayer as well." Phase 1 is this plumbing: no chain, no wallet.

| | The kit guarantees |
|---|---|
| P1 | **Player-look slots.** A slot with `scope: "player"` in `assets.json` resolves per player: that player's loadout value or file when they have one, else the game's. Every game has these by default: `character.body.player`, `character.hat.player` (always declared; optional, and view-only when the game gives players no hat), `character.tint.player`, and each aimed mechanic's colour (`mechanic.projectile.color`). `config/game.json` → `loadout: { slots: [ids], off: [ids] }` adds slots a loadout may set, or keeps some the game's for everyone (`tools/slots.mjs` writes the scope; text and JSON slots never). |
| P2 | **Every copy draws every player in that player's loadout.** The body tint shows on the body. The ring, the nameplate, paint, team colours and every other gameplay colour keep the seat or team colour, so the game reads and scores the same. The player's own shots, stream, drops and splashes use their colour. A new body is put on once the player is on their feet, keeping the ring, held items and the controller. A hat goes on the head socket. Bots wear the game's defaults. |
| P3 | **Loadouts travel with the player.** They go on join and on change, and late or reloaded copies get everyone's. Changing a loadout mid-round updates every screen within about a second. |
| P4 | **A loadout is never fatal.** Unknown slots, wrong types, values outside a slot's range, files other players couldn't load, files over a slot's byte budget, and bodies that are not gf-humanoid-1 rigs are dropped for that player, and the game's own is used instead. |

**Format** (a look in Studio's shape, `creator-studio/docs/web3.md` "Variations"; `kit/assets/loadout.js`):

```json
{ "values": { "character.tint.player": "#23c64a", "mechanic.projectile.color": "#2457ff" },
  "files":  { "character.body.player": "https://…/body.glb", "character.hat.player": { "url": "https://…/hat.glb", "revision": "…" } },
  "pass": null }
```

The checks for each part:
- **Values.**
  - `color` takes `#rrggbb` (`#rgb` is accepted). A `colors` slot (one entry per seat) takes one colour, the player's own.
  - `number` and `integer` must be within the slot's `min`–`max`; `enum` takes one of its options; `boolean` takes true or false.
  - Text and JSON are never part of a look.
- **Files.**
  - An https URL, or a path inside the game with the slot type's extension. A Studio revision carries its `url`; the page resolves revisions before handing the loadout over.
  - `data:` and `blob:` URLs are dropped, because other players couldn't load them.
  - The file must be within the slot's `maxBytes`. A body must pass the runtime rig check (skinned, with the gf-humanoid-1 required bones).
- **Size.** At most 3000 bytes of JSON (one net message).
- **`pass`** is reserved for wallet phase 2+. The play page will put a server-signed pass there (wallet, items, expiry, and a session key made in the player's browser). On join the player would sign the room's challenge with that key, so a stale pass is useless, and the host could refuse items the wallet doesn't own. Phase 1 carries it (opaque, ≤ 2 KB) and never reads it.
- **Phase 1 trusts the client.** Any player can claim any look, and every copy fetches the file URLs a player names. Phase 2 should check the pass, and limit file URLs to the item store's origin.

**Input** (`kit/net/looks.js`). The page hands this player's loadout to the game, before boot or at any time:
- `window.__GF_LOADOUT = loadout` from a same-origin host. A later assignment applies too.
- `postMessage({ type: 'gf:loadout', loadout }, '*')` into the game's frame, from any ancestor window, for the future play page with wallet sign-in. The game says `{ type: 'gf:loadout-ready', v: 1 }` to its ancestors once it listens, and answers each message with `{ type: 'gf:loadout-applied', key, dropped }`.
- `?gf-loadout=<base64url JSON>`, QA only.
- `?gf-show=` subjects wear the page's loadout too, so Studio can render an item's look in the game.

**Net.**
- The pose carries `lk`, the loadout's key (8 hex digits).
- A copy holding a different key for a player asks that player's owner (kit message `lq`, at most every 1.5 s per player). The owner answers with `lo` (the loadout, one message).
- A change is sent to everyone at once, at most twice a second.

**API.**

| Call | What it does |
|---|---|
| `ctx.assets.value(id, fallback, { player: p })` | That player's value: their loadout's for a player-look slot, else the game's. A `colors` slot gives the player's own entry (by `p.seat`) |
| `ctx.assets.model(id, { player: p })`, `texture(id, { player })`, `url(id, { player })` | That player's own file, else the slot's (a failed own file falls back, and is dropped for them) |
| `ctx.assets.own(id, p)` | The player's own value only (undefined without one) |
| `ctx.assets.setLoadout(id, l)`, `loadout(id)`, `onLoadout(fn)`, `playerLooks()` | The per-player store the kit fills (`setLoadout` → `{key, loadout, dropped, changed}`) |
| `ctx.looks.apply(l)`, `ctx.looks.key` | This player's loadout, as the page's message sets it |
| `p.character.setLookTint(c)`, `setHat(obj)`, `look` | The body's own colour (wins over `setTint`, the gameplay tint), the hat, and what it wears now |

Rules that draw something in a player's colour or model read it per player through these calls. They never copy the game's value for everyone.

**Observation.** `window.__game.looks()` → `{ me, local: {key, from}, slots, players: [{id, bot, key, values, files, dropped, drawn: {body, hat, tint, bodyTint, material, mix, visible}, shots: {color, stream, drops}}] }`. `drawn.material` is a tint material's colour read back from the scene, and `shots.stream` is the liquid arc's material tint.

## 6i. Sharp on every screen (kit-owned, on by default; 2026-10-09)

The look's old `quality.<tier>.pixelRatio` is no longer read; `upgrade` removes it from a game's `config/look.json` (and so its slot).
- **Following the screen**: again on every window resize and every devicePixelRatio change (`watchPixelRatio`: a browser zoom, a move to another monitor, the browser's device mode), with the post stack resized with it. Both engines (one boot, §8).
- **The frame-rate guard** (`createGovernor`): while playing in view, after 5 s, a 3 s window under 40 fps lowers the ratio by 15% (never under one CSS pixel); a resize or zoom starts again from the full ratio. `?gf-res=fixed` (QA) turns it off.

## 6j. Panels (kit-owned, on request; open builder M4-D, 2026-10-11)

A shop, an inventory, choice cards, a dialogue and a text field, as one module (`kit/ui/panels/`) that three mechanics had each written for themselves: loot's upgrade cards, build's hotbar and sign editor. The gauntlet (`research/studio-v2/evals/gauntlet/MATRIX.md`) ranks the shop (3 of 25 kinds), the inventory (2), a dialogue (1) and a text field highest among the missing UI parts. A panel **shows and returns a choice**. It holds no game logic: prices, money, stock and what a purchase does are `rules.js` or a mechanic's. A game reaches it through the **`panels` part** (`kit/mechanics/panels`: `{"id": "panels", "params": {"kinds": ["shop", "inventory"]}}`), which brings the words and pictures as slots and hands the panels to `rules.js`; a mechanic calls `ctx.ui.panels` directly.

| | |
|---|---|
| `choice` | `{title, cards: [{id, name, text, image?, tag?, attrs?}], placement: 'center' or 'bottom', modal, keys, dismissable, settle}` → `done`: `{id, index}` (null when dismissed). The keys 1 to 9 pick; a picked card shows for `settle` ms (250). Centre is modal; `bottom` is loot's: the cards sit over the HUD and the player keeps moving |
| `shop` | `{items: [{id, name, text, price, image?, disabled?, reason?, stock?}], currency: {label, amount}, onChoose({id, index})}`. Stays open through any number of buys; `update({items, currency})` redraws in place. A disabled item cannot be chosen; `reason` is the game's own words ("Need 4 more") |
| `inventory` | `{mode: 'bar' or 'grid', items: [{id, name, text, count, image?, node?}], selected, onSelect, actions: [{id, label}], onAction({action, id, index})}`. The **bar** is build's hotbar (non-modal; it scrolls sideways with an arrow where there is more; the keys 1 to 9 and 0 select, or `keys: 'labels'` shows the labels and leaves the keys to the mechanic; `into` mounts it in a container, `barId` and `slotClass` name its DOM); the **grid** is modal with a detail line and the actions. `node` is a drawn icon a mechanic made from its own slots. `select(i)`, `update({items, selected, scroll})` |
| `dialogue` | `{speaker, portrait?, lines, choices?: [{id, text}], cps, instant, onLine}` → `done`: `{choice, index, lines, skipped}`. Types out; a tap, Space, Enter or E finishes the line and then goes on; the choices (and their keys) come with the last line; Esc skips to them |
| `input` | `{title, value, lines (1 to 6), maxLength, required, ids?}` → `done`: the text, or null. Enter adds a row while there is one and does nothing on the last (it never closes under someone typing), Ctrl+Enter or the button confirms, Esc cancels; a one-line field confirms on Enter. This is build's sign editor |

Every call returns a handle `{id, kind, open, remote, refused, done, close(result?), update(patch), select(i), el}`. Common options: `id` (one panel per id: opening it again replaces the first, which settles with null), `for` (a player id), `modal`, `dismissable`, `words` (the strings it says: `title`, `buy`, `close`, `ok` ...), `domId`, `onClose`.

- **Pause.** A panel never pauses the round (§6g: a live round never pauses, and a panel is not the pause menu). A modal panel only takes the local player's input (`ui.cover('panel:<id>')`, so `ui.covered` is true and the controller reads idle) and the mouse (an open pointer lock is let go and taken again on close; the first-person sign editor's trick). Esc closes a dismissable panel and, under a modal one, never opens the pause menu behind it. A game that wants the world to hold still alone can pause itself; the panel does not.
- **Multiplayer.** A panel is local to the copy that opens it. `for: playerId` makes it open only on that player's copy (any other copy gets a handle with `remote: true`, nothing drawn), so code that runs on every copy, or on the host, can name whose panel it is. Its answer comes back on that copy only; telling the host or the others is the caller's message (`ctx.net.send`), as loot's `loot:pick` is. A panel keeps no state a friend could see and sends nothing.
- **Slots.** Words: the part brings one text slot per word of each kind the game uses (`mechanic.panels.<kind>-<word>`, e.g. `shop-buy`, `input-ok`; params `shopTitle`, `shopBuy` ... in `config/game.json`), and a mechanic passes its own (`mechanic.loot.upgrade-title`). Pictures: every file `assets/panels/<name>.png|jpg|webp|svg` is an image slot `panel.image.<name>` (lowercase), and a panel names a picture by that id; a path or a URL is refused. Colours are the game's `--gf-panel`, `--gf-accent`, `--gf-text` (the `ui.*` slots). A drawn icon (`node`) is UI built from a mechanic's own texture slots, never new art.
- **Refusals.** A call the kit can see is wrong (an empty list, a repeated id, a picture that is not a slot, a mode that is not one) logs `gf-three panel refused [<kind>]: <what and the fix>` to the console (verify check 3 reads it), draws nothing and returns a handle with `refused: true`; nothing throws. 12. **Live co-op for 2–4** (track S; PLAN §9 decision 4; forge-core `net.rs`, `snapshot.rs`; `gf/forge/players.js`; `boot-forge.js`). The bar is §6h's: friends in one game, in sync, each seeing the others as a character.
    - **Who simulates whom.** A player's core id is their seat + 1 on every copy. The host's core owns the world and simulates every player: its own, and each joiner's from that joiner's inputs (spawned owned, not local). A joiner simulates only its own player, at once (prediction), and shows everyone else as replicas from the host's snapshots, moving between the last two; nothing on a joiner hurts a replica (`Sim::damage` on a `Replica` deals nothing: the host replays the joiner's shot and its HIT and KILL come back).
    - **Inputs** (`net.rs`): the joiner's core records each fixed step's input under the step's number (`net.record`, Input stage: the stick, the look, the buttons held and pressed, a teleport of its own) and what the step did (`net.predict`, Post); `host.net.takeInputs()` → `net.send('fi', base64, 'host')` about 20 times a second; the host's `host.net.pushInputs(id, b64)` queues them per player (a reload is a new `epoch`) and `net.inputs` applies one per step after a 3-step jitter buffer (repeats the last when dry, idle after 0.25 s, folds in when more than 0.2 s waits), remembering the last applied (`ack`).
    - **Snapshots** ride in the round's own `net.world` message (`createSession({engineWorld})`: the host takes one only when the message will go, about 10–12 a second, so none of its events is lost); a joiner applies each new one before its frame's steps (`net.shared().latest`).
    - **Reconciliation** (`net::reconcile`, in `apply`): the host's state of the joiner's player at its `ack` against the joiner's prediction for that step; a difference over 3 cm (height differences under 6 cm are the snapshot's rounding) moves the present and every later prediction by it, the camera catching up over ~0.1 s (`smooth`), or snaps over 2 m (a teleport, a respawn); a velocity difference over 1 m/s (a knock) is added. The joiner's health is the host's.
    - **Not played twice:** a joiner skips the host's sounds and lights whose source is its own player, and particles of the same name within 1 m of ones it drew in the last 0.6 s (its predicted shot).
    - **Since wave 2 (track G), the host takes a joiner's word for where its own player is.** Every input carries where the joiner's own copy left its player after that step (`StepInput::claim`, 18 bytes); the host still replays the input, then moves its copy to the claim through the world alone (a wall still stops it) and only within 2 m of its own replay (`ADOPT_MAX`). A player is stopped by what its own screen shows. This is a co-op engine: nothing is won by lying about a place within 2 m. Friends walk through each other; a knock is played on the joiner's own step (a PUSH event naming the step); a joiner's copies of enemies have bodies. The snapshot is v3: each player record ends with up to 48 bytes of a plugin's (forge-feel: down, the revive, the reward, the cards held). Measured in a 25 s fight with four players: worst correction 0.07 m (1.17 m on the wave 1b kit), `research/gf-forge/evidence/wave2-G-2026-10-10/`.
    - **Bodies.** Each copy sets every player's `Wear` (forge-core `components::Wear`: the colour (their seat's, or their loadout's §6e), the body's slot index, `hidden` for its own first-person player); `Wear.held` is the core's (forge-feel's weapon switching writes the row in hand; a game with no weapon holds none) and travels in snapshots. - No reticle in the middle (§6d C2 is for the third and first cameras); the canvas shows a crosshair cursor. Movement is relative to the camera's fixed heading. The character's upper body does not pitch to the aim. How to play lists "Mouse: Aim" and "Wheel: Zoom"; Settings leaves out mouse sensitivity and invert look, as for `top`, and check 20 does not ask for them.

| | A round (§3) | A world |
|---|---|---|
| `config/game.json` → `round` | `{seconds, countdown, replay, winBy}` | `{mode: "world", countdown: 0, replay: false}` |
| Phases | lobby → countdown → playing → results → replay | lobby → playing, for good (Quit to menu, Leave world: back to lobby, nothing reset) |

| Player ids | the room's seat id | the tab's `cid` (stable across a handoff; `worldNet` in `kit/net/session.js` translates) |
| Colours | the seat's (`palette[seat]`) | the room's, which follows the tab (gf-multiplayer 1.5.0 `h.color`): the character, its ring and its name match its dot on the world card and in the menu, through a handoff |

| `ctx.net` | `send`, `on` | also `room` (`{key, code, host, max, players}`) and `status` (`menu`, `connecting`, `in`, `handoff`, `full`, `offline`; `alone` without friends) |

**The voxel world** (`kit/world/voxel/`; `config/world.json` → `{template: "voxel", voxel: {...}}`; boot loads it for that template whatever the engine):
- `grid.mjs`: one dense `Uint16Array`, a cell `v = block | tint << 8`, index `(y * sz + z) * sx + x`; 16³ chunks meshed with per-vertex AO, paint as its own attribute (the texture's detail stays under the colour), plants as crossed quads; a ray walk that returns the face entered by.
- `blocks.mjs`: `voxel.blocks[]` (`id`, `label`, `kind`: solid | cutout | glass | glow | plant | sign, `tex`, `place`, `break`, `boom`, `natural`), numbered from 1 in order. **Saved worlds keep the numbers: only ever add blocks at the end.**
- `terrain.mjs`: the island, deterministic from `voxel.terrain` (seed, water, ground, radius, hills, coast, beach, lake, trees, plants, plaza). The play host keeps only the cells players changed, so **`terrain.generator` (1) must give the same island forever**; a change to its output is a new generator version.
- `world.js`: the texture array (one image slot per block texture, `world.voxel.texture.<name>`, drawn at `FACE_SIZES` from `blocks.mjs`: 512 px on the high tier, 256 on the low one; since the creator's "I am not sure why the game looks so blurry still", 2026-10-09: on a 4K screen a 128 px face was stretched 5 to 8 times), the chunk meshes (slot `world.voxel.blocks`), signs (the board in the sign block's texture slot, the words in `world.voxel.sign-ink` on a panel of `world.voxel.sign-paper`), the sea (the look's water slots), one Rapier voxel collider that follows every edit, walls round the world, and the sea's fence: the open sea (2 or more below the water line, reached from the world's edge, not a lake) is solid in the physics only for three cells up from the water line where it meets the land, so nobody walks down the seabed out of sight; a player out at sea under the water anyway is brought back to a spawn after 1.5 s. `ctx.world.voxel`: `grid`, `table`, `apply(x, y, z, v, {text, face})`, `pick(from, dir, max)`, `protectedAt(x, y, z)`, `seaAt(x, z)`, `remeshNow`, `signs`, `store`, `reload()`, `stats()`.
- `default.json`: the kit's default world; `create` writes it for a spec with `world.template: "voxel"`, seeded by the title, the spec's `world.voxel` merged over it, textures from `library/textures/voxel/`, the spawn square in `voxel.protect`.

**Saved on the play host** (`kit/net/persist.js`; the server is `creator-studio/lib/world-core.mjs` behind `/world/v1/<slug>`, or `research/worlds/serve.mjs` here): every copy loads the world from the play host (the newest snapshot plus the edits after it); the room's host pushes the edits it accepted every `saveEvery` s and on `pagehide` (keepalive). Only a room saves: alone (`!ctx.net.active`) the build mechanic loads and polls but never pushes (`build().saves`). Without a published slug (a Studio preview, a local page) the world is `local`: nothing is saved. An edit is `[u, x, y, z, v]` or `[u, x, y, z, v, text, face]`; the server dedupes on `u` and checks bounds, `floor`, `protect`, the block count and sign words against the published `config/world.json`.

**Mechanics.** `build` (`kit/mechanics/build/README.md`): the hotbar, place, break, paint, signs, boom blocks; the host orders, re-checks and saves every edit, catches up arrivals, and takes over after a handoff. `shove`: F or a touch button pushes the nearest player in front (fair play F6: never a knock-down).

**First person** (`camera: "first"`, what a world spec picks since the creator's "Can we make it first person?", 2026-10-09; evidence `research/foundations/evidence/blockhaven-first-person-request-2026-10-09.json`): the eyes at 1.55 m, kept under a ceiling (a ball cast up from the chest: the body is 1.4 m, so in a two-block room a jump would otherwise put them inside the roof); the player's own body is never drawn on their screen, and it turns with the view, so the others see them face where they look (and a shove goes where they look). The input's `cursorMode = 'look'`: where the page allows the pointer lock, any first click only takes the mouse ("Click to look around with the mouse" until it does); then the mouse looks, a click is the action at the crosshair (held while the button is), and the wheel picks the next or previous block (or colour). Where the frame refuses the lock (a post on X), the orbit camera's way: a drag looks, a click is the action at the cursor, and there is no crosshair; on touch, the same taps and long presses (only Jump keeps a kit button). `input.aimFree` says which: the rig's ray goes through the pointer while it is true. The sign editor gives the mouse back to write and takes it again with the key or click that closes it. A crosshair shows while the middle of the screen aims.

**The orbit camera** (`camera: "orbit"`): third person behind the player, the mouse free (the input's `cursorMode = 'drag'`): a drag turns the camera, a click is the action at the cursor (pressed and released in one frame), the wheel zooms between `minDistance` and `maxDistance`; a wall pulls it in as close as `collisionMin` (0.35 m), and closer than 0.9 m the player's own body is hidden. `input.keysPressed()` gives a frame's key edges in the order they went down. On touch a short tap is the primary action where it lands, a long press the secondary; only Jump keeps a kit button. It never asks for the pointer lock, so it plays the same inside a post on X. `config/game.json` → `controls.more: [[keys, what, touch?]]` lists a game's own keys (How to play and the help line show them).

**Observation** (worlds only): `window.__game.camera()` also gives `pitch`, `eye` (the camera's position), `cursor` (the input's mode by name), `aimFree`, `crosshair`, `sensitivity`, `lookScale` and `invertY`, which verify's world checks turn the view with; `window.__game.voxelAt(x, y, z)`, `topAt(x, z)`, `signAt(x, y, z)`, `protectedAt(x, y, z)`, `build()`, `shove()`, `world()`, `project(x, y, z)`; `snapshot().world` = `{status, voxel}`; `snapshot().players[]` carry `color` and `ring` (the colour the ring is drawn in).

## 10. Flat (2D) games (open builder track F, 2026-10-11)

A 2D game is `"engine": "flat"` in the spec with `"plane": "top" | "side"`. It is this kit on a plane, not a fourth renderer: `gf-three.json` → `kit.engine` is `party`, `gf/three/kit.js` → `modules.flat` names the plane, and `gf/three/flat/` carries the four parts that differ (the look with an orthographic camera, the world from a tile map, picture bodies, the controller's flat rig). Everything else in this contract holds as written: boot, the session, live multiplayer, bots, fair play, the menu, the HUD, slots, sounds, flows, verify. `kit/flat/README.md` maps the files and the seams; `kit/flat/ART-STANDARD.md` is the picture standard (`gf-flat-1`).

- **Coordinates.** From above the ground is X-Z at y = 0, screen right is +X and screen up is -Z; nobody jumps. From the side the stage is X-Y, gravity pulls down Y, every body's Z is locked at 0, and Space jumps.
- **The spec.** `camera` is the plane's (`top` | `side`), `world.template` is `field` (top) or `stage` (side), `look.preset` is a flat look (it names the art style: pixel or drawn), every body is `{from: "sprite"}`, and the mechanics are ones run on that plane (`catalog.json` → `engines.flat.mechanics.<plane>`). `world.map` may write the level as rows of text. `create` refuses anything else with the reason, and refuses flat things in a spec that is not flat.
- **The world.** `config/world.json` → `map` (the slot `world.map`, format `gf-tilemap-1`, `kit/flat/tilemap.js`) is the only thing the world is built from: tile kinds (solid, not solid, or a ledge), spawns and named marks. A kind's picture is the slot `world.tiles.<kind>`. `spawns` beside it is §4.3's list, written from the map (`tools/flat-map.mjs --sync`). The runtime adds to §4.3's shape: `world.marks(name)`, `world.cell(p)`, `world.map`, `world.reach()`.
- **Bodies and props** are `image` slots. `ctx.assets.model("prop.<name>")` gives a picture as a card on the plane, so a mechanic that draws its prop needs no change.
- **Checks.** Where a check would assume a 3D game, the part declares what it should read: `gf/three/flat/index.js` → `manifest.reads(plane)`, `worldReport(subject)` (check 17), `bodyReport(image, opts)` (check 19).
- **Tools.** `tools/flat-art.mjs` (the stand-ins in both styles), `tools/flat-judge.mjs` (a picture or a game's pictures against the standard), `tools/flat-map.mjs` (print, report, sync), `tools/flat-reach.mjs` (side-on: drives the real player over every jump the level needs).
