## On the forge engine (this game)

This game runs on **gf-forge**: a Rust core on WebGPU draws and simulates it (the walk, the body, physics, and the weapons, enemies and waves its tracks have landed); the shared kit around it is the same as any game's (the home menu, the HUD, the round, friends, sounds, slots). [CONTRACT §8 forge]({{KIT}}/CONTRACT.md) is the reference; `{{REPO}}/research/gf-forge/README.md` says what runs today. What changes for you:

- **No mechanics.** `config/game.json → mechanics` is empty and stays so. The game's play is its **data tables**, `config/game.json → forge`: `player` (walk, jump, health), `weapons`, `enemies`, `waves`, `cards`. Tune the game there, never in code: every value is a slot (`forge.weapons.<id>.damage`, `forge.enemies.<id>.health`, …) the creator can change in Studio. `node {{REPO}}/research/gf-forge/tools/tables.mjs game/spec.json` (or any JSON with a `forge` block) says what the core accepts and **what runs today** (each table's `RUNS` line): a table that does not run yet keeps its values for later, so never promise it in `text.goal`, the hook or `controls`.
- **`rules.js` on forge: commands in, events out, tables for numbers.**
  - Events out: the core's rule events arrive as `rules.event(ctx, name, {entity, a, b, c, d, remote}, 'forge')` (a wave cleared, a card picked: whatever its tracks emit), and every core event (`'hit'`, `'kill'`, `'spawn'`, `'despawn'`, `'sound'`, `'rule'`, …) can be watched with `ctx.forge.on(kind, (e, ctx) => …)` from `setup` (hits and kills carry `attacker` and `target`: core ids; a player's is their seat + 1).
  - Commands in: `ctx.forge.cmd.setHealth(id, hp, max)`, `ctx.forge.cmd.damage(target, amount, attacker)`, `p.teleport(pos, yaw)`; the weapons' own through `import { FEEL_OP } from './gf/forge/feel.js'` and `ctx.forge.cmd.raw(FEEL_OP.RESET, [id])` (a player starts over: full health, every weapon refilled), `FEEL_OP.LOADOUT, [id, ...rows]` (the weapons rows they hold, the first in hand), `GIVE`, `EQUIP`, `REFILL` (`id` is `ctx.players.nid(p.id)`: their seat + 1). With no command a player holds the rows whose `start` is true.
  - Enemies and waves: the wave director starts with the round on the host and tells you through rule events (`wave-start` {a: number, b: of}, `wave-clear`, `wave-reward`, `waves-done`, `enemy-down` {b: points, d: the killer's id}, `coin` {entity: the player's id, a: value}, `boss-arrive`, `boss-phase`, `boss-down`). A wave whose row has `reward: true` waits for you: define `reward(ctx, {wave, resume})` and call `resume()` when the choice is made. `ctx.ai` has the rest (`spawn(typeId)`, `director.start/stop/skip/state`, `observe()`). `research/gf-forge/specs/room.rules.js` is a whole example.
  - Scores stay yours: `p.score` for each player (co-op too: each their own), `ctx.round.end(reason, winners)` on the host.
- **Players** (`ctx.players.list()`): `p.position`, `p.yaw`, `p.alive` and `p.health` ({hp, max, armor}) come from the core every frame. The host's core simulates everyone (each friend from their inputs); on a friend's copy the others are the host's replicas. Keep game logic under `if (ctx.host)`; never move or hurt another player from a friend's copy.
- **Bots are the core's** (forge-ai): when the round has bots they walk, aim and fire through the same weapons as a player; rules.js may steer one with `bot(ctx, p, dt)`. With friends a round needs two players and has no bots (the kit's). `ctx.bots`, `p.knock` and `fair.*` (gf-three's) do nothing here.
- **The world** (`ctx.world`): `crypt-room` (one torch-lit room) or `ruins-arena` (a moonlit ruined courtyard generated from `world.seed`, with graves the enemies rise from). `spawn(i)`, `zone(name)` (`centre`), `props` (`name → [{at, i}]`), `bounds`. It is built from `config/world.json`; move props there, not in code.
- **First person only**, and the player's own body is never on their own screen (they see their arms and the weapon in hand): friends see it (their seat's hunter in their colour, holding the weapon in hand).
- **Controls** (`config/game.json → controls`): list only what works today. Jump always does; fire, alt fire, reload, the quick melee, the evade and the weapon keys only once the weapons table runs (its `RUNS` line). verify check 13 presses every listed control.
- **verify on forge:** `node {{KIT_TOOLS}}/verify.mjs game --quick` runs the checks that apply through the forge observation interface; every numbered check applies on forge (a check with nothing to judge in this game, such as hits with no weapon, says so and passes); a check shown **"not yet for forge"** never counts against you. It needs WebGPU: the worker passes the GPU in. `--check 3,32` re-runs the boot and the "no WebGPU" screen alone.
- **Never** edit `game/gf/forge/` (its `wasm/` is the pinned core: check 2 compares it byte for byte) and never add a `<script>` or import map to `index.html`.
